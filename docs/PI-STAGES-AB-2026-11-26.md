# Pi 阶段 A、B 交付记录

日期为 2026-11-26，范围为 `feature/desktop-pi`。阶段依据见 [产品与 Pi 迁移规划](PRODUCT-PI-PLAN-2026-11-06.md)。

## 阶段 A 的交付与评分

固定任务与预期事实保存在 [readonly-corpus.json](pi-validation/readonly-corpus.json)。16 个宿主合同场景复用现有 HTTP/SSE 测试，覆盖发现、DM Schema、跨连接同名表、显式目标、批量结构校验、结构模式禁止 SQL、执行事实、危险 SQL、截断、超时、取消、进程退出、追问、连接版本变化、伪造对象与父子任务取消。输入由对应测试中的协议夹具准备，使用随机本地端口、临时配置目录和脚本模型，无业务数据库依赖。

评分要求全部关键合同通过。任务缺失、跳过或失败都不能计为通过。单条运行恰好一个终态，SQL 执行上限为 15 秒和 200 行，目标与执行状态由宿主断言。合同测试通过后，真实模型的回答质量、数据库适配和性能仍单独评分。

从仓库根目录执行以下命令。需先在 Worker、durable-prototype 和 Client 各自执行 `npm ci`，并准备 JDK 21、Maven 和 Node 22.19 以上运行时。

```sh
python3 scripts/validation/pi_stages_ab.py

# 会调用真实模型，需要既有本地 MySQL sys_demo 演示库和 MAIN_CHAT / EXPLORER 模型绑定。
DATA_AGENT_PI_LOCAL_DIRECTORY="$HOME/.data-agent/local" \
  python3 scripts/validation/pi_stages_ab.py --live-mysql
```

脚本在服务端 `target/pi-ab-<时间>/` 输出独立的日志、JUnit XML 和 `summary.json`，记录提交、工作树、工具版本、任务集指纹、实际运行结果与缺失的发布证据。历史 Surefire 文件不能作为本次结果。实时模型/数据库测试默认跳过，报告保留跳过数。输出的合同状态和发布验收状态分别记录。

实库任务复用 `LocalPiMySqlLiveTest`，由独立 SQL 获取计数基准，验证生成的 SQL 结果、目标、执行编号、截断和最终回答。新增空结果案例以及 Java、Pi 直查、Pi Explorer 三组 COUNT 同题对照，每组两次，新建会话避免上下文污染。必须观测到请求的委派方式，不能把模型没有实际执行的路径计为通过。

对照记录耗时、模型与工具调用、输入输出 Token、用量完整性、模型配置和实际查询结果。工具调用数同时从事件轨迹计数，避免 Java 的聚合统计少计工具。Java 返回原始 SQL 结果，缺少 Pi 信封中的 executionId 和 target；报告明确保留该差异，Java 组通过独立计数和请求默认目标核验，不补造执行证据。主模型沿用同一 MAIN_CHAT 绑定，Explorer 沿用已有 EXPLORER 绑定，Java 与 Pi 的完整工具集和模型调用预算仍有差异。因此本轮对照作为实库冒烟基线，后续框架或协作收益评估需固定这些变量。两个样本只报告逐次数据，不据此设定 p95。当前未配置模型单价，Token 不能转换为真实账单成本。

本轮运行结果保存在 [results-2026-11-26.json](pi-validation/results-2026-11-26.json)。最终离线验证为 Core 25 项、Durable 16 项、后端本地测试 245 项、前端 51 项通过，另有 14 项需显式开启的实库测试跳过；16 个固定宿主合同均通过。前端 TypeScript 检查和生产构建通过，仍有已有的 Browserslist 与产物体积提示。

本轮 MySQL + Qwen 共通过 12 个场景，包括 5 个原有只读案例、1 个新增空结果案例和 6 次同题执行。独立 SQL 基准为 12 行，三组各两次均返回正确计数。Java 两次约为 2.9 / 3.3 秒，Pi 直查为 8.1 / 9.7 秒，Explorer 为 13.0 / 31.3 秒。该简单聚合任务里 Explorer 的委派增加了耗时。最后一次 Explorer 的 `usageComplete=false`，不能据部分 Token 宣称成本收益。上述实库验收前后配置指纹均一致。

### 阶段 A 剩余验收

- 本机仅配置了 MySQL，DM8 的真实 Schema、查询、追问、失败和取消需配置可用测试连接后执行。DM 夹具覆盖不能替代实库结果。
- 已补“本月活跃用户”未定义时先澄清的提示约束和实库回归。初次输出发现模型推测月份后，约束收紧为直接询问口径与具体年月；最终两次请求都以 `PI_MODEL_ERROR` 中断，保留失败记录，完整口径案例待复验。更多领域口径仍需业务人员审阅。
- 完整 Java/Pi 和单助手/Explorer 对照需控制模型、权限、数据、工具与预算，提前冻结正确率、延迟和成本阈值。上述冒烟样本不能支持切换发布入口或增加并行角色的决策。

## 阶段 B 的选型决定

Core / pi-ai 从 1.4.0 升级到 1.5.0 的改动见提交 `d0e5775`。现有 25 个真实 Worker 子进程测试覆盖缺失字段、枚举、边界值、参数转换、可选 null、额外字段、分块参数和非法流式参数，以及工具往返、预算、取消和多轮会话。本轮重新运行这些测试。历史实库记录来自原版本，以上 MySQL 场景则使用本轮锁定的 1.5.0。尚未取得 1.4.0 / 1.5.0 / Durable 的完整同题实库对照。

本轮选择继续使用 **Core 1.5.0**，沿用临时前台会话。默认 Worker 路径仍为 `Data-Agent-Pi-Worker/src/worker.js`。Durable 保留为原型。依据是现有只读产品链路已经接通，Durable 的恢复收益尚未覆盖新增维护与数据保留成本，且若干行为仍未对齐。

### 实际存储清单

新增存储检查会读取真实 SQLite 的全部表，并在 `durable-prototype/target/storage-inventory.json` 记录表名、行数和样例标记是否出现。当前样例确认系统提示词、用户消息、模型输出和工具结果确实保存。数据库还有会话、entries、任务、提交、documents 及版本记录。旁路 journal 保存会话映射、模型非秘密配置、运行映射与出站事件，包括工具参数、文本和状态。

样例 API Key 在 SQLite、WAL、SHM、journal 和 stdout 中均未命中。测试模型不接收数据库密码，不能由此推出所有任意工具结果都已脱敏。原型没有按会话删除协议，退出只关闭存储，文件继续存在。试验由测试临时目录负责清理。采用前需要明确允许保留的内容与周期，并为 SQLite 和 journal 共同设计清理。当前完整聊天不归档的产品策略继续由 Core 内存路径承接。

### 复评条件

明确需要后台长任务、Java 重启后接回任务或长时间审批等待时，重新评估 Durable。复评需先补齐工具和模型预算、完整用量统计、数据清理、R3–R7 和平台分发证据，再用同一只读任务集与 Core 比较。压缩、追加指令和写入迁移按选型继续拆解，现有 Pi `/compact` 仍返回不支持。

阶段 B 的交付是已有证据、继续 Core 的决定和上述复评条件。阶段 A 在 DM8 与完整同条件评测完成前维持进行中。

## 同日后续小步

Core 的 `PI_MODEL_ERROR` 现在可以附带 `modelError`，只包含固定错误分类、可识别的 HTTP 状态和最后一次模型调用耗时。Java 再次校验这些字段，将它们放入终态和运行日志，用现有 runId 关联。原始厂商报文、响应头和密钥不进入这些字段。Worker 也不再将完整模型错误文本写入 stderr。分类包括 AUTH、RATE_LIMIT、TIMEOUT、STREAM、NETWORK、HTTP 和 UNKNOWN，无法识别的原因保留 UNKNOWN。

模型失败或中途取消时，用量标记为不完整，避免默认的零 Token 被计为完整统计。回归覆盖真实 Worker 的 401 与不完整流，以及宿主丢弃诊断中的任意字符串字段。

实库验证仍复用 `LocalPiMySqlLiveTest`。新增 DM 模式通过已有配置中的连接 ID、Schema 和表名启动；只读基准与查询工具使用同一个目标。覆盖命名空间发现、结构、计数、连续追问、空结果、真实 SQL 错误和模型流式取消。MySQL 保留原来的演示任务与入口，两种数据集每次只运行一种。

```sh
# 替换为本地配置中的真实连接 ID、测试 Schema 与测试表。
DATA_AGENT_PI_LOCAL_DIRECTORY="$HOME/.data-agent/local" \
DATA_AGENT_PI_DM_CONNECTION_ID=2 \
DATA_AGENT_PI_DM_SCHEMA=TEST_SCHEMA \
DATA_AGENT_PI_DM_TABLE=TEST_TABLE \
python3 scripts/validation/pi_stages_ab.py --live-dm
```

DM 模式将报告写入 `target/pi-dm-live-summary.json`，验证脚本还会保存到本次独立报告目录。当前配置只有 MySQL，DM 实库结果仍待获得。DM 驱动层的 200 行截断还需要有足够数据的测试用例。

本轮重新跑通了 MySQL 结构与计数、业务口径澄清两项真实模型用例。口径用例没有调用数据库工具，先询问“活跃”的定义与具体年月，先前中断的口径验收已补上。具体结果追加在原结果文件的 `followUp` 字段，原有失败尝试继续保留。

验证清单中的 150 秒已明确为事件间空闲超时，与宿主现有实现一致。

本轮离线回归通过 Core 26 项、Durable 16 项、后端本地测试 246 项、前端 51 项；实库用例默认跳过 15 项。新增 DM 路径完成编译和入口检查，尚未作真实数据库验收。
